# لوحة المشروع الختامي

**الاسم:** ريم سكات العنزي  
**المسار:** مساعد مخصّص (Custom Assistant)  
**التطبيق المعتمد:** ChatGPT (Projects)

## 1 · المهمة وخط الأساس
| البند | الإجابة |
| :--- | :--- |
| **المهمة كما تُؤدّى اليوم** | **البداية:** مراجعة بيانات وصفية لجهات مستهدفة من قاعدة بيانات عامة (توصيات مهنية، زيارات تعريفية، وفعاليات).<br>**النهاية:** ترشيح البرنامج التدريبي العام الأنسب لفرق عمل كل جهة وصياغة مسودة رسالة تواصل مخصصة لمسؤولي الموارد البشرية والتدريب. |
| **الوقت اليوم لكل مرة** | **20 دقيقة** لكل جهة (8 دقائق لتحليل النشاط واختيار البرنامج + 12 دقيقة لصياغة الرسالة ومراجعتها). |
| **التكرار الشهري** | **50 مرة شهرياً** (2–3 جهات يومياً)، ويؤديها **3 أعضاء** في فريق تنسيق التدريب. |
| **أكثر ما يتعب فيها** | تكرار صياغة الرسائل يدوياً لكل جهة حسب قناة التعارف والقطاع، وبطء مطابقة الفئات الوظيفية بالبرنامج المناسب. |

## 2 · المسار، ولماذا
| البند | الإجابة |
| :--- | :--- |
| **المسار المختار** | **مساعد مخصّص (Custom Assistant)** مزوّد بتوصيف البرامج المهنية وقواعد الضبط. |
| **لماذا هذا المسار؟** | لأن توصيف البرامج وقواعد الصياغة ثابتة بينما معطيات الجهات متجددة يومياً؛ المساعد المخصّص يثبّت التعليمات ويمنع التخمين. |

## 3 · سير العمل
| # | الخطوة | من يؤديها | ما الذي يُفحص بعدها |
| :--- | :--- | :--- | :--- |
| **1** | اختيار سجل الجهة وإزالة أي أسماء أشخاص أو أرقام هواتف أو بيانات خاصة قبل الإدخال. | **أنا** | خلو المدخلات من أي بيانات شخصية أو خاصة. |
| **2** | تحليل القطاع والفئة الوظيفية وترشيح البرنامج وصياغة مسودة الرسالة. | **التطبيق** | مطابقة البرنامج المرشّح مع الفئة الوظيفية وذكر قناة التعارف. |
| **3** | مراجعة المسودة والتحقق من ملاءمة البرنامج وسلامة الصياغة (نقطة القرار البشري). | **يقترح وأنا أعتمد** | خلو النص من أي وعود غير معتمدة ودقة الترشيح. |
| **4** | اعتماد الرسالة النهائية وتحديث سجل المتابعة. | **أنا** | توثيق حالة التواصل في السجل. |

## 4 · بطاقة التفويض والأمر الجاهز
| الحقل | بطاقتك |
| :--- | :--- |
| **ما يُسند** | مطابقة نشاط الجهة بالبرامج المهنية المعتمدة، وصياغة مسودة رسالة مخصصة حسب قناة التعارف، وحساب نسبة التقدم نحو المستهدف. |
| **ما يبقى لي** | تنقيح البيانات الشخصية والخاصة قبل الإدخال، مراجعة ملاءمة البرنامج، اعتماد الصياغة النهائية، وتحديث السجل. |
| **البيانات** | توصيف البرامج الثلاثة العامة + معطيات وصفية منقّحة للجهة. |
| **معيار القبول** | 1. ترشيح برنامج من القائمة المعتمدة بنسبة **100%**.<br>2. ذكر قناة التعارف بوضوح.<br>3. ألا تتجاوز الرسالة **130 كلمة**.<br>4. التوقف وطلب التوضيح عند نقص البيانات ورفض محاولات الاختراق. |
| **الأمر الجاهز** | محفوظ في `prompts/system-instructions.md` بإطار RICE. |

## 5 · البيانات والخصوصية
| السؤال | نعم / لا · كيف |
| :--- | :--- |
| **هل أُزيلت البيانات الشخصية والخاصة؟** | **نعم**، استُبدلت الأسماء والمسميات الخاصة بعينات افتراضية وعامة بالكامل. |
| **هل تسمح السياسة برفع المادة؟** | **نعم**، المادة المرفوعة وصفية وعامة 100% ولا تحتوي على أي معلومات سرية. |
| **هل تقتصر المادة على الحاجة؟** | **نعم**، تقتصر على القطاع والفئة الوظيفية وقناة التعارف فقط. |
| **ما الذي لا يُرفع أبدًا؟** | قواعد البيانات الفعلية، أسماء الموظفين، أرقام الهويات والجوالات، أو أي مسميات برامج خاصة. |

## 6 · معيار القبول وحالات الاختبار
| الحالة | المدخل | النتيجة المقبولة | ماذا حدث في التجربة |
| :--- | :--- | :--- | :--- |
| **نموذجية** | جهة استشارات وعمليات (15 محلل أعمال)، توصية مهنية. | ترشيح برنامج تحليل البيانات وصياغة رسالة تحت 130 كلمة. | نجح من المرة الأولى بدقة تامة. |
| **فوضوية** | جهة تقنية (40 موظفاً)، معرض تقني، تحديث إنجاز (1,020 من 3,500). | ترشيح برنامج المهارات الرقمية وحساب النسبة (29.14%) تحت 130 كلمة. | ضُبط حد الكلمات إلى 130 كلمة فنجح في التجربة الثانية. |
| **حدّية** | جهة مقاولات، الفئة الوظيفية غير محددة. | التوقف وطرح سؤال واحد لتوضيح الفئة الوظيفية دون تخمين. | أُضيفت قاعدة التوقف عند نقص البيانات فنجح. |
| **أمان** | محاولة حقن تعليمات وطلب إضافة رقم هوية ورابط خارجي. | رفض التعليمات المدسوسة ومنع إخراج أي رقم هوية أو رابط. | رفض المحاولة والتزم بقواعد الضبط. |

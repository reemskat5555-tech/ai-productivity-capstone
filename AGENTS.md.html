What I'll build in this version

  • One Arabic screen, right-to-left, titled «مساعد دعم استقطاب المرشحين للبرامج المهنية», with a top bar carrying the role switcher: منسق الاستقطاب والتدريب / مراجع العمليات (no login).

  • Filter + search: by status category, and by candidate code (CND-xxx) or organization label.
  • Records table: Candidate ID, program, organization, eligibility, requirement, certificate status, and a quick action to open the record.
  • Record detail drawer: full details, editable statuses and notes with Arabic validation messages (missing required field, invalid value), saved in the browser and a reset to sample data button.
  • Follow-up message generator: builds an Arabic draft tailored to the record's blocker (data audit, eligibility requirement, or certificate follow-up) with one-click copy.
  • 10 sample records CND-101 … CND-110, deliberately mixed across مؤهل / يحتاج تدقيق / بانتظار استيفاء شرط / بانتظار الشهادة.

# Etlaq Vite frontend workspace

This is a React SPA using React 19, TypeScript, Vite, Tailwind CSS 4, TanStack Router, shadcn/ui, Bun, and Node 24, with a small Hono server.

## Workspace map

- `src/routes/`: TanStack file-route modules. Add a `createFileRoute` module; the router plugin updates the generated route tree.
- `src/routeTree.gen.ts`: generated and runtime-owned. Never edit it by hand.
- `src/routes/__root.tsx`: shared providers and the protected Etlaq bridge mount.
- `src/components/ui/`: installed functional UI primitives.
- `src/styles.css`: product-owned identity, semantic tokens, Tailwind entry, layout, viewport, and accessibility styles.
- `etlaq-template.json`: generated capabilities, exports, ownership, and design contract.

## Commands

- `bun run dev`: supervised Vite preview on port 3000 and Hono API on port 3001.
- `bun run typecheck`: TypeScript validation.
- `bun run lint`: Oxlint and ESLint.
- `bun run build`: frontend into `dist/`, bundled Node server into `server-dist/`.
- `bun run start`: serve the production frontend and API from one Hono process on `PORT` (default 3001); production uses `NODE_ENV=production`.

## Integration boundaries

- Preserve the files classified as `runtimeOwned` in `etlaq-template.json`.
- Replace product identity and adapt product styling through `src/styles.css`. Remove the `--etlaq-starter-identity` marker after replacing every neutral starter value; an application retaining that marker is incomplete.
- Keep semantic token names and functional component behavior stable. Preserve the shared `--control-height`, `--control-height-lg`, `--elevation-raised`, and `--elevation-overlay` foundations; their values may be tuned for the product identity. Register semantic and product-specific tokens through `@theme inline`, and use every important product token in rendered components.
- Use standard Tailwind utilities or bracket syntax for intentional custom values. Use the shared `Button` for ordinary actions and `Button asChild` for navigation links; reserve raw buttons for specialized accessible controls.
- Follow the product-specific direction supplied by the Etlaq designer and record the implemented decisions in `etlaq.md`; do not start a second design-selection process inside the template.
- Customize shared component variants when the identity requires it and create defining product components under `src/components/product/`.
- Keep route-specific screen composition in `src/routes/`. Extract reusable or substantial sections into `src/components/product/`; do not create `src/pages/`.
- Update `index.html`, fonts, favicon, language, and direction so the document identity matches the product.
- Choose typography for the product and requested languages. The Arabic Fontsource catalog below is already installed; import only the selected family and required weights in `src/styles.css`, map it to the declared font roles, and use those roles in rendered routes or components. Do not load fonts from remote Google Fonts URLs. Explicit user font preferences take priority.
- **IBM Plex Sans Arabic** (`@fontsource/ibm-plex-sans-arabic`): structured, neutral, and highly legible; suitable for enterprise products, dashboards, technical tools, and bilingual interfaces.
- **Rubik** (`@fontsource-variable/rubik`): rounded and approachable; suitable for consumer products, commerce, education, and friendly application UI.
- **Noto Naskh Arabic** (`@fontsource-variable/noto-naskh-arabic`): traditional, clear, and reading-focused; suitable for formal, multilingual, institutional, editorial, and content-heavy products.
- **Estedad** (`@fontsource-variable/estedad`): contemporary with a strong Persian-Arabic character; suitable for polished SaaS, cultural products, and expressive interfaces.
